# lhg-wb-bluebook 冒烟测试

标准用例：每次怀疑 skill 自身有缺陷时运行。全部用例必须先读对应章节全文再判定，不凭印象。

## 路由测试（问 → 必须定位到）

| # | 用户提问 | 期望路由 | 判定标准 |
|---|---|---|---|
| R1 | "workbuddy 怎么装 skill？" | `ch05-Skill.md` | 回答引用 ch05 的 Skill 标准结构，不自创安装路径 |
| R2 | "我想让它每天早上给我发资讯汇总" | `ch15-资讯整合.md` + `ch10-自动化任务.md` | 跨章两章都读，答案含定时设置做法 |

## 质量门（任一命中即失败）

- Q1 未读章节全文就回答（凭印象编功能路径）
- Q2 只讲概念、没给"目标 → 操作 → 验收"步骤或指令模板
- Q3 菜单位置、按钮名等易变细节未标注"书里是这么写的，当前版本请核对"
- Q4 回答用了中文以外的语言
- Q5 引用 Skill 安装 / 制作时没用 ch05 / ch22 的标准结构

## 记录格式

`用例 / 通过 / 失败 / 备注` —— 失败项进入质检报告，并注明对应 SKILL.md 的章节。
